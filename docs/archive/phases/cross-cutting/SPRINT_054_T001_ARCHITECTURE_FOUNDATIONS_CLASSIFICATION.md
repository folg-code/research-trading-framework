# Sprint 054 T001 — `ARCHITECTURE_FOUNDATIONS.md` Section Classification

## Methodology and scope

This artifact is the read-only classification output required by Sprint 054
T001 (`docs/planning/sprints/SPRINT_054.md`), applying the four-way
classification framework already established by
`docs/historical/REPO_WORKFLOW_DOCS_AUDIT.md` Phase 6b (CURRENT / FUTURE /
MIXED / AMBIGUOUS) to every major section and numbered subsection of
`docs/vision/ARCHITECTURE_FOUNDATIONS.md` (1,557 lines, read in full across
four passes: lines 1–400, 400–800, 800–1200, 1200–1557).

For each section, classification was based on:
1. the section's own framing language (normative "must"/"should" vs.
   descriptive "the framework has"/named concrete types), and
2. a targeted code/test verification pass — `docs/reference/MODULE_MAP.md`
   (the current package map) plus `Grep` searches in `src/trading_framework/`
   for the concrete types, modules, or fields the section names (e.g.
   `SignalOccurrence`, `DatasetLifecycleState`, `ExecutionMode`,
   `reproducibility_status`).

Per **D-S054-02**, sections that could not be confidently classified from a
reasonable amount of reading + grep-level verification are marked
**AMBIGUOUS** rather than guessed as CURRENT — a false "current" label is
worse than leaving something classified as uncertain a little longer. No
content in `ARCHITECTURE_FOUNDATIONS.md` was moved, edited, or rewritten to
produce this table; the actual move (if any) is T004, gated on this
classification being reviewed.

Two purely navigational/meta sections (§1 Purpose, and the un-numbered
`## 4 Core Philosophy` / `## 6 Domains` headers) describe the document
itself rather than a behavior — these are noted as **N/A (meta)** rather
than forced into the four-way scheme, per the same "don't guess" principle.

## Notable findings

- **No section is purely FUTURE.** Every subsection that reads as forward-looking in the vision index's framing (per the audit's "long-term model" characterization) turned out, on a full read plus grep-level verification, to have at least a partially- or fully-built counterpart in `src/trading_framework/`. This is a different picture from `MULTITIMEFRAME_MARKET_MODEL_ARCHITECTURE.md` (T003), which the audit already flagged as having a *known* future-labeled-but-built section — `ARCHITECTURE_FOUNDATIONS.md` skews the other way: mostly-built content still living entirely in `vision/`.
- **§6.5 Execution Domain / §9 item 4 is the most consequential MIXED finding.** The domain scaffolding (orders, fills, positions, broker abstraction, paper broker) is built, but `execution/modes.py` currently supports only `DRY_RUN` — Replay and Live Execution, both named as available runtime modes in the vision text, are not yet supported "in the current increment" per the code's own docstring. Any T004 split must not present Replay/Live as CURRENT.
- **§4.12's promotion lifecycle (`Local Working → ... → Released Framework Component`, `reproducibility_status = EXPERIMENTAL`) has no code counterpart at all**, despite the underlying identity/versioning primitives (`component_id`, `definition_hash`) being pervasively implemented. This is a genuine sub-section-level split, matching D-S054-01's warning that section-level moves would be too coarse for this file.
- **§4.10's planner-observability metadata** (`candidate_count`, `estimated output size`, "applied constraints") has no matching field anywhere in `src/`, even though the broader "bounded search space" concept is realized through Robustness Research's experiment/variant model.
