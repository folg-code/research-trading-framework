
# `DATA_MODULE.md` Section Classification

## Methodology and scope

This artifact applies the same four-way classification framework Sprint 054
established (CURRENT / FUTURE / MIXED / AMBIGUOUS, per
`docs/historical/REPO_WORKFLOW_DOCS_AUDIT.md` Phase 6b and used by
T001–T003/T003b, e.g.
`docs/planning/sprints/SPRINT_054_T003b_WORKFLOWS_AI_ADR_ARCHITECTURE_CLASSIFICATION.md`)
to every major section and numbered subsection of
`docs/reference/modules/DATA_MODULE.md` (674 lines, read in full).

This work finishes the open item Sprint 054 T007 flagged and left pending a
maintainer decision (`docs/reference/README.md`'s "Flagged (Sprint 054 T007
§3)" note on this file).

For each section, classification is based on:
1. the section's own framing language (normative "must"/"should"/"suggested
   location" vs. descriptive claims of built behavior), and
2. a targeted code verification pass — `Grep`/`Read` across
   `src/trading_framework/market/`, `src/trading_framework/application/market_data/`,
   and `src/trading_framework/infrastructure/{providers,importers,storage,normalization,validation}/`
   for the concrete types, enums, modules and workflows the section names
   (e.g. `MarketQuote`, `DatasetLifecycleState`, `MissingRangeCalculator`,
   `ReplayClock`, retention-policy enums, roll-policy/adjustment-method
   types), and cross-checked against `docs/reference/system/MODULE_MAP.md`
   §5 "Market Data Implementation Map" (a Sprint-054-produced, currently
   accurate as-built reference for this same domain).

Per **D-S054-02**, sections that could not be confidently classified from a
reasonable amount of reading + grep-level verification are marked
**AMBIGUOUS** rather than guessed as CURRENT. No content in `DATA_MODULE.md`
was rewritten to produce this table; the classification is read-only, the
actual move is a direct follow-on step in the same change.

## Resolution of the stale "Roadmap alignment" section

Confirmed stale as flagged in the task brief. The subsection's claim that
"everything beyond Phase 2A is PLANNED/GATED" does not match the codebase:
`MarketTrade` is built (contradicting its own "PLANNED" label for Phase 2C),
and a substantial continuous-futures pipeline (contract identity, roll
policy, materialization, dataset lifecycle integration) exists that the
Roadmap alignment note does not acknowledge at all. `MarketQuote` remains
the one accurate "not yet built" claim in that subsection. The subsection is
moved verbatim to `docs/vision/DATA_MODULE_FUTURE.md` with an explicit
"verified stale as of this reclassification" annotation directly above it,
rather than edited or deleted, per the "preserve content verbatim" scope
rule — deciding whether to rewrite or delete it outright is left to a future
maintainer decision, not made unilaterally here.

## Notable findings

- **Partitioning policy (§19) is a genuine, previously undocumented
  divergence, not just aspirational text**: the codebase partitions by
  `session_date=<date>` (one partition per exchange session day) for both
  bars and trades, not by the documented monthly default. This is worth a
  human decision on whether to update the vision default to match reality
  or treat day-based partitioning as a bug — flagged here, not resolved.
- **Continuous futures (§21) has real but much narrower machinery** than
  documented: one roll policy (volume-based, RTH close) and zero adjustment
  methods (no backward/forward diff/ratio), versus the 4 roll policies × 5
  adjustment methods the vision text enumerates.
- **This file's own two internal "roadmap" sections (§2 Roadmap alignment,
  §29 Initial Implementation Scope) are both stale in the same direction**:
  both understate what is built (particularly around continuous futures and
  dataset finalization/publication), which is exactly why Sprint 054 T007
  flagged this file as needing the same rigor as the vision-tier documents
  rather than being trusted at face value.
