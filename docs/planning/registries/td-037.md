## TD-037 — `apps/cli` and `apps/workbench` Are Not Mypy-Checked by CI or Pre-Commit

```text
Status: ACCEPTED
Priority: MEDIUM
Domain: apps/cli, apps/workbench (workspace-wide tooling)
Discovered: Sprint 064 T007 (2026-09-14), while adding apps/workbench/src/workbench_core/windows_process.py
Target Review: Before either package's next significant new module, or the
  next time a real mypy-catchable bug ships in either package
Owner: Unassigned
```

### Accepted Shortcut

Neither the "Quality" CI job (`uv run mypy`, root `pyproject.toml`) nor the
local pre-commit hook (`uv run --all-packages mypy`) actually type-checks
`apps/cli` or `apps/workbench`. Root `[tool.mypy]`'s `files` list is
`["src", "tests", "apps/dashboard/src", "apps/dashboard/pages",
"scripts/dashboard"]` — `apps/cli` and `apps/workbench` are absent, and
neither package's own `pyproject.toml` declares a `[tool.mypy]` section, so
mypy silently has nothing of theirs to check under either invocation.
`apps/dashboard` is unaffected — it is explicitly in the root `files` list.

This was discovered by accident: an ad-hoc `uv run mypy apps/workbench`
(passing an explicit path, which bypasses the `files` list entirely and
picks mypy's own default discovery instead) surfaced a real bug —
`windows_process.py`'s module-level `_kernel32: WinDLL | None` was
dereferenced without narrowing at several call sites — that the "passing"
pre-commit/CI mypy runs had never actually exercised. The bug was real and
was fixed in the same commit that discovered this gap (Sprint 064 T007); this
entry is about the coverage gap itself, not that specific bug.

### Reason

Not a deliberate design choice — the root `[tool.mypy]` `files` list was
never updated when `apps/cli` (Sprint 046) and `apps/workbench` (Sprint 064
T004) were added as uv workspace members. `CLI ruff`/`Dashboard ruff`/CI's
per-package `pytest` jobs give a false impression of parity with
`apps/dashboard`'s treatment, but dashboard is the only one of the three
apps mypy actually reaches.

### Consequences

- Every commit and every CI run for `apps/cli` and `apps/workbench` source
  has proceeded on ruff + pytest signal only, for type-safety purposes,
  since each package's creation. A type error that ruff cannot catch
  (attribute access on a possibly-`None` value, an `Any` leaking through a
  third-party call with no stubs, a signature mismatch across module
  boundaries) can ship silently in either package.
- Both `apps/cli/CLAUDE.md` and `apps/workbench/CLAUDE.md` (and this
  session's own work) treated "mypy clean" as an accomplished gate for
  those packages' PRs; that claim was not actually being verified by the
  tooling it was attributed to.
- `apps/dashboard` does not have this problem — it is in the root `files`
  list.

### Safe Operating Boundary

Until repaid, a contributor who wants real mypy coverage for a change under
`apps/cli` or `apps/workbench` must run mypy against that path explicitly
(e.g. `uv run mypy apps/workbench --ignore-missing-imports`) as a manual,
extra step -- not something CI or the pre-commit hook does automatically.
`--ignore-missing-imports` (or per-package stub dependencies) is needed
because neither package currently pins type stubs for its third-party
dependencies (e.g. `pyyaml`) the way that matters once real config
discovery applies.

### Repayment Trigger

Either package's next significant new module, or the next time a real bug
mypy would have caught ships through one of them (as nearly happened here).

### Repayment Direction

Not prescribed here. The two live options are (1) add `"apps/cli/src",
"apps/cli/tests", "apps/workbench/src", "apps/workbench/tests"` to the root
`[tool.mypy]` `files` list, accepting whatever first-run cleanup that
requires (each package's own dependencies -- `pyyaml`, `aiohttp` -- may need
`[[tool.mypy.overrides]]` entries or installed stub packages), or (2) give
each package its own `[tool.mypy]` section plus its own CI/pre-commit
invocation, matching `apps/dashboard`'s isolation more literally. Either way,
this is a maintainer decision, not a unilateral test-file or config edit.
